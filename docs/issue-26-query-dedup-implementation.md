# 后续设计：Query 与 Practice 的内容独立性（不属于 Issue #26 交付）

- 更新：2026-09-28
- 状态：待单独立项、校准与实现；不是当前 CI 的门禁或验收条件
- 关联：本次范围和已生效规则见 [Issue #26 的设计决策](issue-26-query-source-decision.md)

## 为什么另立任务

当前 `--check-discipline` 只检查 Query 与 Practice 的标题、`applies_when` 是否明显复述。一个 Query 也可能复制正文的 Guidance、anti-pattern、例外或行动顺序，甚至用同义词把结论改写成问题；这会让“命中”无法说明场景表达是否独立。但检索需要共享领域术语和真实业务对象，不能把所有词语重合当成作弊。

这属于**测试样本质量**，与“给定已冻结样本时 Pack 能否被检索”的 #26 门禁不同。先收敛 PR 自动执行，再用独立任务扩展样本审阅，不在本次引入新阈值或伪称已覆盖正文。

## 拟定的处理逻辑

1. **审阅对象**：对新建或改写的 Query，比较其与目标及容易混淆的相邻 Practice 的标题、适用条件和正文各类决策内容。保留必要的产品名、API 名和领域词；重点找复制的独有表达、答案性指令和步骤顺序，而不要求场景与 Practice 在语义上无关。
2. **区分两种疑点**：一是 Query 本身写入了 Practice 的结论，使标签显而易见；二是 Query 通过复制原文才取得高检索排名。前者由内容审阅判断，后者可辅以保持原意的独立表述作对照；检索排名不能反向决定正确标签。
3. **分级而非盲目硬拒绝**：确定的长段复述或明显答案泄漏可失败；共享术语、短 Query、多个合理目标、合法引用等进入人工复核。未复核前不能标作已通过。仅有语义相似、词面重合或一个不自然的“删除术语后查询”都不足以单独判失败。
4. **人工结论可追溯**：复核时记录为什么保留术语、为什么目标是该 Practice、是否需要改写 Query 或承认边界不清。若发现两个 Practice 都合理，应先解决标签/Practice 边界，不能为了门禁随意改 `expect`。
5. **渐进接入**：先对新/改 Query 产出不阻塞的审阅报告，使用真实正常场景、明显照搬、长专业术语、短 Query 与邻接边界样例校准误报/漏报；只有规则与复核责任明确后，才决定哪些高置信度情况进入 CI 硬门禁。旧 fixture 不因未经校准的新规则一次性变红。

任何去词或改写对照都必须保留原始场景的意图；若场景被破坏，结论为证据不足，而非认定“依赖照搬”。不能用自动判定取代维护者对 `expect` 和 neighbor 边界的确认。

## 另行评估的相邻事项

- 来源、审核人和标签依据的可靠记录：旧 fixture 中批量填充的 `origin: regression` 已移除，因为它不等于真实来源证明。若需要溯源，先明确可核实的来源及审核责任，不能仅批量补元数据。
- Query 中 secrets、PII、prompt injection 或危险指令的安全检查：需要自己的误报处理和安全政策，不应顺带塞进正文相似度检查。
- Agent 候选 Query、真实请求脱敏样本、上下文摘要与下游行为验证：各有不同的真值和权限边界，不能直接改变固定 fixture 的 CI 结论。

这些后续议题可以共用审阅记录，但不能合并成 #26 的隐藏验收条件。实现时优先复用现有 evaluator 的输入和证据，不在当前 PR 预先构建未校准的术语库、语义模型或新工作流。
